# Summoner.world: private-reviewed, sealed zero-reward Quiz answer service

This is a **server-only staging service**, not a public/new Quiz mode. All existing public Quiz answers, wallet, stake, profession XP, Summon tickets and draw/growth code remain unchanged. Do not present this as player-available competitive Quiz. It cannot award spendable items.

## Implemented receipt boundary

- `QuizPrivateRound` already stores 256-bit secret nonce, independently Ed25519-attested three question IDs and answer commitment, exact two player IDs, and six per-player exposure receipts in one transaction. That prior subsystem stays feature-gated OFF by default. This stage adds `QuizPrivateAttempt` with unique round/player key, sealed submitted three-index answer JSON and SHA-256 answer digest, server-calculated score, and receipt timestamps.
- Service `submitProtectedQuizAnswers` requires a caller supplied by a separately authenticated server workflow, validates exact participant identity and three 0-3 indexes, and takes a **round-level PostgreSQL advisory lock**. It audits the original reviewer signature, commitment, nonce, six exposure rows and every prior answer/score before writing. Six simultaneous retries of the same choices create one attempt; submitting different choices is rejected permanently.
- When both source-authenticated players have answered, the same transaction computes objective scores and a single immutable `protected-quiz-resolution-v1`-style receipt: two sorted scores, winner or tied outcome, frozen answer IDs, original salted commitment, nonce revealed **only after completion**, exact reviewer-backed answers, finalized time, all currency/XP/ticket totals hard-set zero. SHA-256 hash is stored next to the receipt. Reopening recomputes all scores and compares exact receipt bytes and hash; a forged score or edited receipt fails closed.
- `expireProtectedQuizRound` only permits a no-show void when the stored 15-minute deadline has passed. A one-player timeout never manufactures a win, payout or career XP. Duplicate expiration is idempotent.
- `getProtectedQuizAnswerView` is server-only, requires one of the two original player IDs and returns unanswered/answered flags without opponent choices or nonce before finalization. It discloses the original nonce/answers **only after immutable finalization** to support eventual independent verification. No HTTP route uses this service yet; future consent-based invitation and session-bound routes are separate work.
- `QuizPrivateRound.resultJson/resultHash/finalizedAt` and `QuizPrivateAttempt` are **additive** PostgreSQL migration changes. Unique constraint on (round,user) plus check constraints protect score/hash bounds and finalization state. Public QuizDuel and all financial tables are unchanged. New migration MUST NOT run on live data until a separately reviewed rollout.
- Important limitation: the presently staged `reserveProtectedQuizRound` takes two IDs but does not implement a mutual-acceptance invitation. It cannot safely be exposed as a general public endpoint yet. No source key, secret nonce or payout service is automatically enabled by this PR. Human-reviewed genuine bank population, anti-bot/collusion/cooldowns, appeal handling and rollout readiness remain independent prerequisites.

## Acceptance

`scripts/test-protected-quiz-answer-policy.ts` tests exact three-choice validation, sealed digests, mutation sensitivity and invalid indexes. Extended `scripts/test-protected-quiz-round-db.ts` uses isolated localhost `summoner_verification`, creates two distinct test users and 96 ephemeral offline-signed protected questions; tests six simultaneous same-key answer retries, no early reveal, no cheating third party, corrupt scores, edited final hash, deterministic winner, no-show timeout, opponent readback, and no credited XP, tickets or cash. Original reservation/exposure and protected bank tests must remain green. Fresh/legacy migration recovery, TypeScript, lint, production build, browser flows and native iPhone Simulator/unsigned archive are required gates.

The currently fixed public bank remains zero-stake practice. A private match after completion must not be interpreted as proof of independent human accounts or economic reward eligibility.
